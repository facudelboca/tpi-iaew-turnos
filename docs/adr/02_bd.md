
## ADR-002: Base de datos

**Estado:** Aceptado

**Contexto:**
El dominio del sistema corresponde a la **Reserva de Turnos de Salud**, que comprende las entidades `Paciente`, `Profesional`, `Especialidad` y `Turno`. Este tipo de sistema exige:
1. **Integridad referencial estricta:** Un turno debe asociarse indefectiblemente a un paciente, profesional y especialidad válidos.
2. **Control estricto de concurrencia y solapamientos:** La agenda médica no puede permitir dobles reservas para un mismo profesional en el mismo horario.
3. **Consistencia transaccional (ACID):** El flujo de reserva (validación de agenda, bloqueo de slot horario y confirmación/emisión del turno) requiere garantías atómicas e inmediatas para evitar condiciones de carrera.
4. **Relaciones estructuradas:** Los profesionales poseen agendas fijas (`diasAtencion`) y pertenecen a una especialidad médica determinada (`especialidades`), ajustándose de forma natural al modelo relacional.

**Decisión:**
Adoptar **PostgreSQL 16+** como motor de base de datos relacional principal junto con **Sequelize ORM** para Node.js, complementado con scripts DDL de migración (`src/migrations/init.sql`).

**Alternativas consideradas:**
- **MongoDB / NoSQL (Documental):** Descartado. Si bien ofrece esquemas flexibles, la garantía de no solapamiento y la integridad referencial en documentos anidados o colecciones separadas requiere delegar excesiva lógica transaccional y validaciones complejas en la capa de aplicación. En un sistema de turnos de salud, la integridad de los datos y las claves foráneas relacionales ofrecen mayor confiabilidad y robustez.
- **MySQL / MariaDB:** Considerado, pero PostgreSQL ofrece mejores características para el manejo de tipos de datos avanzados, soporte robusto de índices compuestos (`btree`, `gist`/`range` para rangos temporales si fueran requeridos), y excelente compatibilidad en contenedores Docker y entornos cloud.

**Consecuencias:**
- Se implementan claves foráneas (`FOREIGN KEY`) con restricciones de integridad referencial (`ON DELETE RESTRICT` en turnos y especialidades, y `ON DELETE CASCADE` en agendas del profesional).
- Se definen índices compuestos optimizados (ej. `(profesional_id, fecha_hora_inicio, estado)` y `(paciente_id, fecha_hora_inicio)`) para búsquedas rápidas de agenda y prevención de solapamientos.
- Las reservas se ejecutan bajo transacciones ACID seguras.
- Se reemplaza el contenedor de MongoDB por PostgreSQL 16 en el `docker-compose.yml`, incluyendo volumen persistente y script de inicialización automático.
